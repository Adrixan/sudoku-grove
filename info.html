Informatik hinter dem Sudoku

1. Das Spielfeld im Speicher

Für den Computer ist das Spielfeld kein Quadrat, sondern eine Liste (Array) mit 81 Zahlen. Eine 0 steht für ein leeres Feld. Die Felder werden Zeile für Zeile durchnummeriert, beginnend bei 0. So lässt sich aus dem Index eines Feldes ausrechnen, wo es liegt:

  • Index = 9 · Zeile + Spalte (Zeile und Spalte ab 0 gezählt)
  • Zeile = Index geteilt durch 9, ohne Rest; Spalte = Rest dieser Division (Modulo)
  • Block = 3 · (Zeile geteilt durch 3) + (Spalte geteilt durch 3), jeweils ohne Rest

Zeilen, Spalten und Blöcke heißen im Programm Einheiten: Es gibt 27 davon. Jedes Feld teilt sich mit genau 20 anderen Feldern eine Einheit. Diese Nachbarn darf es nie mit derselben Ziffer geben.

const zeileVon = (i: number) => Math.floor(i / 9);
const spalteVon = (i: number) => i % 9;
const blockVon = (i: number) =>
  Math.floor(zeileVon(i) / 3) * 3 + Math.floor(spalteVon(i) / 3);

Ausprobieren: Wähle ein Feld

Klicke auf ein Feld oder gehe mit den Pfeiltasten durch das Gitter. Die 20 Nachbarn werden markiert.

Weil der Löser diese Rechnungen Millionen Mal braucht, rechnet das Programm sie beim Start einmal für alle 81 Felder aus und speichert die Ergebnisse in Tabellen. Nachschlagen ist schneller als jedes Mal neu dividieren.

2. Kandidaten als Bitmaske

Welche Ziffern passen noch in ein leeres Feld? Das Programm merkt sich das nicht als Liste, sondern als eine einzige Zahl: Jede der 9 Ziffern bekommt ein Bit. Bit 1 steht für die 1, Bit 9 für die 9. Ist ein Bit 1, ist die Ziffer noch möglich.

Mit Bitoperationen rechnet der Prozessor damit in einem einzigen Schritt: ODER (|) vereinigt zwei Mengen, UND (&) bildet die Schnittmenge, NICHT (~) dreht alle Bits um. Die Anzahl der gesetzten Bits (der Popcount) ist die Anzahl der Kandidaten.

const bit = (z: number) => 1 << (z - 1); // 5 wird zu 0b000010000
let maske = 0b111111111;                // alle 9 Ziffern möglich
maske &= ~bit(7);                       // die 7 streichen
const passt5 = (maske & bit(5)) !== 0;  // ist die 5 noch möglich?

3. Zufall mit Startwert

Ein Computer würfelt nicht. Ein Pseudozufallszahlengenerator (PRNG) berechnet aus einem Startwert (englisch Seed) eine Folge von Zahlen, die zufällig aussieht. Gleicher Startwert, gleiche Folge: Das ist kein Fehler, sondern genau das, was wir brauchen.

  • Eine Hashfunktion (cyrb128) verwandelt einen Text wie daily-2026-11-03 in vier 32-Bit-Zahlen. Schon ein anderes Zeichen ergibt ganz andere Zahlen.
  • Der Generator sfc32 („Small Fast Counting“) mischt diese vier Zahlen mit Addition, Verschiebung und XOR bei jedem Aufruf neu und liefert die nächste Zahl.
  • Das Tagesrätsel nutzt das Datum als Startwert. Darum hat in Österreich jedes Gerät am selben Tag dasselbe Rätsel, ganz ohne Server.
  • Für „Neues Spiel“ holt das Programm den Startwert aus crypto.getRandomValues, dem Zufall des Betriebssystems.

Ein PRNG wie sfc32 ist gut für Spiele, aber nicht für Passwörter oder Verschlüsselung: Wer den Startwert kennt, kennt alle Zahlen.

4. Der Generator

Ein neues Sudoku entsteht in drei Schritten:

  1. Volles Gitter bauen: Der Löser aus Kapitel 5 füllt ein leeres Gitter. Weil er die Ziffern in zufälliger Reihenfolge probiert, entsteht jedes Mal eine andere gültige Lösung.
  2. Ziffern entfernen: Das Programm nimmt Ziffern paarweise heraus, Feld i und Feld 80 − i. So sieht das Rätsel punktsymmetrisch aus. Nach jedem Schritt prüft es zwei Dinge: Gibt es noch genau eine Lösung? Und ist das Rätsel nicht schwerer als die gewünschte Stufe? Wenn nicht, kommen die Ziffern zurück.
  3. Bewerten: Am Ende misst die Bewertung (Kapitel 6) die Schwierigkeit. Passt sie nicht, beginnt ein neuer Versuch mit dem Startwert …#1, …#2 und so weiter. Reicht die Symmetrie für schwere Stufen nicht, entfernt das Programm zusätzlich einzelne Felder.

5. Der Löser: Backtracking

Der Löser probiert systematisch: Er wählt ein leeres Feld, setzt eine passende Ziffer ein und macht weiter. Landet er in einer Sackgasse (ein Feld hat keinen Kandidaten mehr), geht er einen Schritt zurück und probiert die nächste Ziffer. Dieses Zurückgehen heißt Backtracking, das Verfahren ist eine Tiefensuche in einem Suchbaum.

  • Trick „wenigste Möglichkeiten zuerst“ (englisch minimum remaining values): Der Löser wählt immer das Feld mit den wenigsten Kandidaten. Ein Feld mit nur einem Kandidaten ist gar keine Entscheidung. So bleibt der Suchbaum klein.
  • Eindeutigkeit beweisen: Der Löser hört nach der ersten Lösung nicht auf, sondern sucht eine zweite. Erst wenn der ganze restliche Suchbaum ohne zweite Lösung durchsucht ist, steht fest: Das Rätsel hat genau eine Lösung.
function suche(feld: number[]): number {
  const i = feldMitWenigstenKandidaten(feld);
  if (i === -1) return 1;            // alles voll: eine Lösung gefunden
  let loesungen = 0;
  for (const z of kandidaten(feld, i)) {
    feld[i] = z;                     // versuchen
    loesungen += suche(feld);        // rekursiv weitersuchen
    feld[i] = 0;                     // zurücknehmen (Backtracking)
    if (loesungen >= 2) break;       // zweite Lösung: nicht eindeutig
  }
  return loesungen;
}

Achte im Demo auf die Zähler: Nach der ersten Lösung nimmt der Löser alle Versuche wieder zurück, um nach einer zweiten Lösung zu suchen. Bei einem eindeutigen Sudoku gibt es darum am Ende genauso viele Rücknahmen wie Versuche. Bei einem leichten Sudoku ist jeder Versuch ein Treffer, bei einem schweren muss der Löser auch falsche Wege gehen.

6. Wie schwer ist es? Die Bewertung

Mit Backtracking löst der Computer jedes Sudoku in Millisekunden. Über die Schwierigkeit für Menschen sagt das nichts. Darum gibt es einen zweiten Löser, der wie ein Mensch vorgeht: Er rät nie, sondern nutzt nur logische Lösungstechniken und nimmt immer den einfachsten Schritt, den er findet. Die Stufe richtet sich nach der schwierigsten Technik, die er braucht. Diese Schritte sind auch die Tipps im Spiel.

Lösungstechniken und ihre Stufe

7. Technik der Webseite

  • Web Worker: Ein schweres Sudoku zu bauen kann eine Sekunde dauern. Das passiert in einem eigenen Thread, damit die Seite währenddessen nicht einfriert.
  • Service Worker: Beim ersten Besuch speichert der Browser alle Dateien des Spiels. Danach funktioniert es auch ohne Internet und lässt sich wie eine App installieren (Progressive Web App).
  • Datenschutz: Der Spielstand liegt nur im Speicher deines Browsers (localStorage). Es gibt keine Anmeldung, keinen Server für Spielstände und keine Tracker. Eine Content Security Policy verbietet der Seite, irgendetwas von fremden Servern zu laden.
  • Tests: Über 40 automatische Tests prüfen den Code, zum Beispiel dass jedes erzeugte Sudoku genau eine Lösung hat und dass kein Tipp der Lösung widerspricht. Sie laufen vor jeder Veröffentlichung.

Der ganze Quellcode ist offen: github.com/Adrixan/sudoku-grove. Die Spiellogik steckt in src/engine/: grid.ts (Spielfeld), rng.ts (Zufall), solver.ts (Backtracking), techniques.ts und rater.ts (Bewertung), generator.ts und hints.ts (Tipps).

8. Zahlen, Fakten, Quellen

  • Es gibt 6 670 903 752 021 072 936 960 verschiedene vollständig ausgefüllte 9×9-Sudoku-Gitter (Felgenhauer und Jarvis 2006).
  • Ein Sudoku mit eindeutiger Lösung braucht mindestens 17 Vorgaben. Mit 16 geht es nie: Das wurde mit einer riesigen Computersuche bewiesen (McGuire, Tugemann und Civario 2014).
  • Sudoku in beliebiger Größe (n² × n² Felder) ist NP-vollständig (Yato und Seta 2003). Niemand kennt ein Verfahren, das große Sudokus immer schnell löst. Für 9×9 ist der Suchbaum zum Glück klein genug.
